# ATDD Checklists

This directory contains **Acceptance Test-Driven Development (ATDD)** implementation checklists for all stories.

## Purpose

ATDD checklists guide developers through the **Red-Green-Refactor** cycle:
- 🔴 **RED**: Tests written first (define expected behavior)
- 🟢 **GREEN**: Implement code to pass tests
- 🔵 **REFACTOR**: Improve code quality while keeping tests green

## Directory Structure

Each checklist follows the naming convention:
```
story-{epicId}-{storyId}-{feature-name}.md
```

**Example**:
- `story-9-1-metrics-exposure.md` - Story 9.1: Metrics Exposure
- `story-1-20-health-check.md` - Story 1.20: Health Check API

## How to Use

1. **For Tea (Test Engineer)**:
   - Generate ATDD checklist when starting a new story
   - Create failing tests in `tests/integration/` or `tests/unit/`
   - Document expected behavior and acceptance criteria

2. **For Dev Team**:
   - Open the checklist for your assigned story
   - Follow tasks in order (Day 1 → Day 4)
   - Check off completed items
   - Run tests frequently to verify progress

3. **For QA/Review**:
   - Use checklist to verify all acceptance criteria are met
   - Ensure all tests pass before marking story complete
   - Validate Definition of Done

## Checklist Structure

Each checklist includes:
- ✅ **Test Status** - Which tests are failing (RED phase)
- ✅ **Implementation Tasks** - Step-by-step guide organized by day
- ✅ **Verification Commands** - How to test each step
- ✅ **Acceptance Criteria Mapping** - Test → AC → Implementation task
- ✅ **Definition of Done** - Completion criteria

## Commands

```bash
# List all checklists
ls -1 tests/atdd-checklists/*.md

# Open checklist for current story
cat tests/atdd-checklists/story-9-1-metrics-exposure.md

# Verify RED phase
go test -v ./integration/metrics/

# Track progress
grep -E "\[x\]|\[ \]" tests/atdd-checklists/story-9-1-metrics-exposure.md
```
