## User Story

**作为** 平台开发者  
**我希望** CLI 命令能够自动从 REST API 定义生成  
**以便** API 变更时 CLI 自动保持一致，减少手动维护成本，避免 API-CLI 不一致

---

## Business Value

### 问题陈述
当前挑战：
- ❌ REST API 更新后需要手动同步 CLI 命令
- ❌ API 和 CLI 维护双倍工作量，容易不一致
- ❌ 新增 API 端点时需要重复编写 CLI 代码
- ❌ 参数验证、类型定义、文档在 API 和 CLI 中重复

### 解决方案价值
- ✅ **单一真相源**：OpenAPI Spec 作为唯一定义
- ✅ **自动化一致性**：API 变更自动反映到 CLI
- ✅ **零维护成本**：CLI 代码自动生成，无需手动编写
- ✅ **类型安全**：编译时检查参数类型和必填项
- ✅ **开发提效**：新增 API 功能自动获得 CLI 支持

### 投资回报（ROI）
- **开发效率提升**：预计节省 60% CLI 开发时间
- **维护成本降低**：避免 API-CLI 不一致导致的 bug
- **功能交付加速**：新 API 立即可用 CLI 调用

### Task 3: 模板设计（1 天）
**目标**：设计高质量的代码生成模板

#### 3.1 Cobra 命令模板（`command.tmpl`）
```go
// Code generated by cli-generator. DO NOT EDIT.
package generated

import (
    "github.com/spf13/cobra"
    "apprun/pkg/cli"
)

// New{{.CommandName}}Command creates the '{{.CLIPath}}' command
func New{{.CommandName}}Command(client *cli.APIClient) *cobra.Command {
    var (
        {{range .Flags}}
        {{.VarName}} {{.Type}}
        {{end}}
    )
    
    cmd := &cobra.Command{
        Use:   "{{.Use}}",
        Short: "{{.Short}}",
        Long:  `{{.Long}}`,
        RunE: func(cmd *cobra.Command, args []string) error {
            // API 调用
            req := &{{.RequestType}}{
                {{range .Flags}}
                {{.FieldName}}: {{.VarName}},
                {{end}}
            }
            
            resp, err := client.{{.APIMethod}}(cmd.Context(), req)
            if err != nil {
                return err
            }
            
            // 输出格式化
            return cli.PrintResponse(resp, cmd.Flags())
        },
    }
    
    // Flags
    {{range .Flags}}
    cmd.Flags().{{.FlagFunc}}(&{{.VarName}}, "{{.FlagName}}", {{.Default}}, "{{.Description}}")
    {{if .Required}}cmd.MarkFlagRequired("{{.FlagName}}"){{end}}
    {{end}}
    
    return cmd
}
```

// Code generated by cli-generator. DO NOT EDIT.

import (

func (c *APIClient) {{.MethodName}}(ctx context.Context, req *{{.RequestType}}) (*{{.ResponseType}}, error) {

        "{{.Path}}",
        req,
        &resp,
    )

### Task 5: Makefile 和 CI 集成（1 天）

```makefile
# 生成 CLI 命令
generate-cli:
	@echo "🔄 Generating CLI from OpenAPI..."
	@go run scripts/codegen/cli-generator.go \
		--openapi docs/swagger.yaml \
		--output core/cmd/generated \
		--client-output core/pkg/cli/generated \

clean-generated:
	@rm -rf core/cmd/generated/ core/pkg/cli/generated/
	@echo "✅ Generated code cleaned"

# 检查一致性
check-cli-consistency:
	@echo "🔍 Checking API-CLI consistency..."
	@make generate-cli
	@git diff --exit-code core/cmd/generated/ core/pkg/cli/generated/ || \
		(echo "❌ Generated CLI is out of sync with OpenAPI spec. Run 'make generate-cli'" && exit 1)
	@echo "✅ API-CLI is consistent"

# 构建前先生成
build: generate-cli
	cd core && go build -o bin/apprun
```

#### 5.2 GitHub Actions Workflow
创建 `.github/workflows/generate-cli.yml`：

```yaml
name: Generate CLI from OpenAPI

on:
  push:
    paths:
      - 'docs/swagger.yaml'
      - 'core/handlers/**'
      - 'core/modules/*/handler.go'
  pull_request:
    paths:
      - 'docs/swagger.yaml'
      - 'core/handlers/**'

jobs:
  generate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      # 1. 更新 Swagger 文档
      - name: Generate Swagger docs
        run: |
          cd core
          go install github.com/swaggo/swag/cmd/swag@latest
          swag init -g main.go -o ../docs
      
      # 2. 生成 CLI 命令
      - name: Generate CLI commands
        run: make generate-cli
      
      # 3. 验证生成的代码可编译
      - name: Build generated CLI
        run: |
          cd core
          go build ./cmd/generated/...
      
      # 4. 运行测试
      - name: Test generated CLI
        run: go test ./core/cmd/generated/...
      
      # 5. 提交生成的代码（仅 push 事件）
      - name: Commit generated code
        if: github.event_name == 'push'
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git add core/cmd/generated/ core/pkg/cli/generated/ docs/swagger.*
          git diff --staged --quiet || \
            git commit -m "chore: regenerate CLI from OpenAPI [skip ci]"
          git push
      
      # 6. PR 检查：验证一致性
      - name: Check consistency (PR only)
        if: github.event_name == 'pull_request'
        run: make check-cli-consistency
```

## Technical Details

### 技术栈

| 组件 | 技术选型 | 版本 | 原因 |
|------|---------|------|------|
| OpenAPI 解析 | `github.com/getkin/kin-openapi` | latest | 完整的 OpenAPI 3.0 支持 |
| 代码生成 | Go `text/template` | stdlib | 灵活、类型安全 |
| CLI 框架 | Cobra | v1.8+ | 已集成（Story 1.6） |
| HTTP Client | `net/http` + 封装 | stdlib | 轻量、可控 |
| 表格渲染 | `github.com/olekukonko/tablewriter` | latest | 美观、易用 |
| YAML 解析 | `gopkg.in/yaml.v3` | v3 | 已集成 |
| JSON 处理 | `encoding/json` | stdlib | 标准库 |

### 数据结构

#### CLICommand（内部数据模型）
```go
// scripts/codegen/types.go
type CLICommand struct {
    // 基本信息
    Name          string   // 命令名称（如 "AuthLogin"）
    CLIPath       string   // CLI 路径（如 "auth login"）
    Group         string   // 命令分组（如 "auth"）
    Use           string   // Cobra Use 字段
    Short         string   // 简短描述
    Long          string   // 详细描述
    
    // API 信息
    OperationID   string   // OpenAPI operationId
    Method        string   // HTTP 方法（GET/POST/PUT/DELETE）
    Path          string   // API 路径（如 "/api/auth/login"）
    
    // 参数
    Flags         []Flag   // CLI 参数列表
    
    // 输出
    OutputFormat  string   // 默认输出格式（table/json/yaml）
    SuccessMsg    string   // 成功消息模板
    
    // 类型
    RequestType   string   // 请求类型名称
    ResponseType  string   // 响应类型名称
}

type Flag struct {
    Name        string   // 参数名称（如 "email"）
    FlagName    string   // CLI flag 名称（如 "email"）
    ShortFlag   string   // 短 flag（如 "e"）
    Type        string   // Go 类型（string/int/bool）
    Required    bool     // 是否必填
    Default     string   // 默认值
    Description string   // 描述
    EnvVar      string   // 环境变量名（可选）
}
```

### OpenAPI 扩展字段映射

| OpenAPI 字段 | CLI 映射 | 示例 |
|-------------|---------|------|
| `paths[path][method]` | Cobra Command | `POST /api/auth/login` → `apprun auth login` |
| `operationId` | 方法名称 | `authLogin` → `NewAuthLoginCommand()` |
| `summary` | Cobra Short | "User login" |
| `description` | Cobra Long | 详细描述 |
| `parameters[].name` | Flag name | `key` → `--key` |
| `parameters[].required` | MarkFlagRequired | `true` |
| `parameters[].schema.type` | Flag type | `string` → `StringVar` |
| `x-cli-command` | CLI path | `auth login` |
| `x-cli-flag` | Custom flag name | `--config-key` |
| `x-cli-short` | Short flag | `-k` |

### 错误处理策略

#### 生成时错误
```go
// 缺少必填字段
if cmd.OperationID == "" {
    return fmt.Errorf("operationId is required for path %s %s", method, path)
}

// 无效的扩展字段
if !isValidCLICommand(cmd.CLIPath) {
    return fmt.Errorf("invalid x-cli-command format: %s", cmd.CLIPath)
}
```

#### 运行时错误
```go
// API 调用失败
if err != nil {
    return cli.FormatError(err)  // 统一错误格式化
}

// 参数验证失败
if email == "" {
    return fmt.Errorf("--email is required")
}
```

## Risks & Mitigations

### 风险 1: OpenAPI Spec 不完整
**影响**: HIGH  
**概率**: MEDIUM  
**缓解措施**:
- 在 CI 中强制执行 OpenAPI 验证
- 提供 OpenAPI Linter 检查必填字段
- 开发者指南明确要求添加扩展字段

### 风险 2: 生成的代码与手写代码冲突
**影响**: MEDIUM  
**概率**: LOW  
**缓解措施**:
- 生成的代码放在独立目录（`cmd/generated/`）
- Git ignore 生成的代码（可选策略）
- 清晰的命名规范避免冲突

### 风险 3: 模板维护成本高
**影响**: MEDIUM  
**概率**: MEDIUM  
**缓解措施**:
- 模板版本化管理
- 提供模板测试工具
- 文档化模板变量和函数

### 风险 4: 代码生成失败导致构建中断
**影响**: HIGH  
**概率**: LOW  
**缓解措施**:
- 生成器错误处理健壮
- CI 中独立的生成验证步骤
- 保留上次成功生成的代码作为 fallback
